# Leather-jacket survivor

Historical first reconstruction. The owner subsequently chose the blue Vault 42
suit and crouch/IK refinement; the current asset and controls are described in
`docs/PLAYER_VAULT42_2026-09-05.md`.

The owner rejected the rounded figure and the contour antialiasing. The new
model takes its clothing silhouette and locomotion direction from Fallout 2's
male leather-jacket character, retaining the previously requested older man.
The leather-jacket option was used as the stated default pending outfit feedback.
This is an original 3D reconstruction, not an extracted Fallout mesh or sprite.
It is not a pixel-exact reproduction: our camera, lighting, older head and
continuous animation differ from the original prerendered frames.

## Editable source and runtime

- `blender/build_survivor.py` builds shaped cross-section meshes, real jacket
  lapels/yoke/zip/pockets, fitted charcoal trousers with compression creases, a leather
  sleeve and bare opposite arm, flat-soled laced boots, curled fingers and a
  planar face with swept grey hair. All colors are authored in sRGB and exported
  in linear space. Blender supplies the split vertex normals.
- `assets/characters/survivor.blend` contains the original meshes, materials,
  named armature, and Idle / Walk / Jog / Brace / Turn actions. The actions are
  exported from the game's actual pose solver, so Blender previews its behavior.
- `assets/characters/survivor.mesh` is the compiled triangle-corner export:
  HFCHAR01 header; little-endian material and part counts; linear color,
  roughness and flags per material; named parts with material-grouped triangle
  corners (position and split normal, six floats). The loader embeds the bytes
  into the executable. 15 articulated parts, 15 shared materials, 369,393 bytes.
- This is rigid bone-weighted articulation with overlapping garment joints,
  not a continuously deforming multi-weight skin or a cloth simulation. It uses
  the existing dynamic-instance ray-tracing path on Metal and Vulkan.
- `survivor.rs` owns distance-paced stance/swing IK, hip reach correction,
  torso/pelvis counter-rotation, arm swing opposing the feet, heel/toe roll,
  stance asymmetry, breathing, turning and actual-collision bracing/release.
- `survivor.inc` is compiled verbatim into both shading backends. Garment
  grain, faded knees, scuffs and boot-adjacent soil follow bind coordinates
  rather than swimming through world space. Fine material frequencies fade
  with pixel footprint; this does not blend primary visibility or silhouettes.
  Material `tex_index` values -2 through -16 identify these character surfaces;
  nonnegative values retain the image-texture meaning and -1 is untextured.

## Antialiasing

All look AA defaults are zero. Config resolves AA and AA_SOFT to zero even
when an old launch environment supplies nonzero values. The AA settings rows
are removed. The existing backend AA dispatch remains dormant; the game uses
the centre primary ray and nearest integer upscale, with no contour softening.

## Rebuild

From the repo root (Blender 4.5.3 was used):

```sh
blender -b --factory-startup --python blender/build_survivor.py
cargo test -p rt-viewer export_blender_motion -- --ignored
blender -b --factory-startup --python blender/build_survivor.py
cargo build --release
```

The first Blender pass generates the runtime geometry. The explicit Rust
harness writes `output/player-reference/motion.txt`; the second Blender pass
imports those poses into editable actions. The game doesn't read that review
file. On this Mac Blender and the Metal viewer need to run outside the agent
sandbox; Blender otherwise faults during startup before running the script.

Reference inspected: [Fallout 2 male leather-jacket animation sheet](https://www.spriters-resource.com/pc_computer/fallout2/asset/54201/),
with six directions and idle/walk/run sequences. The older head is an intentional
adaptation. Reference pixels are kept only in ignored review output and are not
part of the game asset.

## Verification

- 210 workspace tests pass; the manual Blender-motion export also passes.
- A red/green regression reproduced the old limb-roll bug: vertical links
  retained world-forward fronts instead of following the body's heading.
- The exported mesh passes finite/nondegenerate Metal geometry checks, unit
  normal checks and complete dynamic-part registration.
- A 600-tick walk/jog/turn/stop test places every exported vertex in its actual
  pose and checks ground penetration and body bounds. Existing stance, knee
  length and wall-brace/release regressions also pass.
- Release compilation validates GLSL; in-game captures validate Metal runtime
  shader compilation on Apple M2 Pro. Vulkan runtime is unavailable on this Mac.
- Blender's Walk action at frame 50 matches all 15 runtime bone transforms
  within 0.0001 after coordinate/bind-space conversion.
- Captures with legacy `AA=1 AA_SOFT=1` versus zero overrides differ by at most
  1/255, with mean channel differences below 0.00016/255 (the known Metal
  cross-run numerical variation). Both configurations resolve to zero AA.
- The 930-frame, 15.5-second Metal recording covers walking, turns, wall
  contact/release and jogging. Final scene: 209 primitives, 357,168 triangles.

Review output lives under `output/player-reference/` (ignored in git).
`player.png` is the final close-up; `walkthrough.mp4` is the verified H.264
recording; `motion-review.png` and 20 selected PNG frames retain pose evidence.
